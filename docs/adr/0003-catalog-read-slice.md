# ADR 0003 — Empty database-backed catalog read slice

2026-10-02: owner assigned catalog website with database and chose empty catalog, real data later. Authorizes additive catalog-read migration and backend/UI, not payments, fake product seeds, source approval bypass or public production release before D10 evidence.

D09 public projections implement a deliberately read-only vertical slice. `catalog_read.public_product/public_sku` are derived safe facts, never D01 canonical product/SKU or D02 offering/price/stock authority. No seller/media placeholders or fictional entity IDs seeded. Locked projection fields/constraints live in migration001; transport allowlist in shared catalog contracts; no prices/stock exposed until actual canonical D02/D03 integration. UUID identity/slug/category/pagination follow D01.

Only canonical publication verifier may produce projection records in a future assigned write task after D01 source/size chart/dictionaries/media/seller and D02 eligibility validation. There is no importer, publisher, Admin mutation route or grant in this slice. Reader has SELECT on visible views only, not source tables. Receipt expiry≤60seconds bounds stale visibility; future publisher needs renewal/withdrawal evidence and approved media serving. No products can appear until those dependencies exist. Projection schemas may be rebuilt, never used to seed canonical entities or replace source validation. Media URLs restricted to safe same-origin approved derivatives; media serving remains blocked until actual assets exist.

Fresh empty Neon inspection is pre-migration baseline; only new schema/role added transactionally, no existing data overwritten. Record migration digest/idempotent replay, retain original owner connection only for scoped maintenance; a separate random reader credential stored ignored `.env.catalog` is used by running API. Reader cannot write/DDL and no public grant. No dump/DR claim from empty baseline: independent encrypted backup/restore, hosting/DNS/budget/runtime secret management remain public production release gates.

Read routes `/v1/catalog/products` and `/v1/catalog/products/:id` bounded/scoped parameterized queries, live visibility checks/no cache, fail unavailable rather than false empty on DB failure. Child SKU cursor separate. Website SSR uses backend-only configured origin, no browser secret; no cart/quote/order/payment affordance. Search/filter navigation doesn't create indexable facets; noindex remains. Canonical product stale slug301 via Next route handler; canonical product same across B2B/B2C. Bad IDs/query/cursors controlled400; invisible product404; unknown database state503.

Catalog-only implementation is distinct from a public hosting deployment. Local browser exercise is verification of actual code/data connection, not a fake production launch. Existing CI plus targeted privacy/pagination/failure/reader-privilege checks required; no fixture products written to real Neon. Production hosting requires exact resource/budget/deployment/backup readiness evidence, which this task must report honestly if absent.
