# Product media v1 — executable scope

Owner locks 9 gallery images plus one optional video. Migration004 supersedes maximum20 in intake v1. No applied migration is edited. PostgreSQL position CHECK1..9 plus product-row lock prevent concurrent commands exceeding cap; slot count is rechecked inside transaction. Existing galleries>9 abort activation rather than purging data.

setImageColor payload: assetId,colorId,declaration. Asset must belong to current product, color active and used by a canonical SKU. Generate immutable <=240px WebP thumbnail, share one color association across sizes. Reassign via sourced audited versioned command, preserve old evidence/media. PostgreSQL composite foreign key prevents cross-product asset association. Every color needs mapping before future publication. Gallery images/thumbnail source are still unapproved; mapping does not grant rights.

uploadVideo payload: base64,alt,rights. Initial simple implementation accepts prepared MP4 <=8MiB, H.264 yuv420p, one video stream/no audio, <=720px on each axis, <=30fps and <=60s. Does not upload camera MOV originals. Use local FFmpeg conversion under explicit owner instruction to choose excerpt; the 454MB82.32s source was inspected and owner chose first30s. Original untouched. Prepared clip720x406/30fps/30s,1.87MB before backend normalization.

Backend verifies MP4 header and FFprobe metadata, then decodes/reencodes with constrained threads, bitrate, timeout and protocol whitelist, strips metadata and generates WebP poster. One processing operation per instance, fails503 busy/unavailable; unsupported or oversized input fails400. Temp directory removed in finally, no source path/URL from client. Write immutable MP4/poster privately with create-only generation precondition; product_video PK allows exactly one. Rights evidence,audit,outbox,command receipt and version increment atomic; stale/revoked actor rechecked after processing. If final transaction fails, immutable orphan retained for later controlled reconciliation; no purge/delete grant.

This bounded v1 is synchronous prepared-file intake, replacing the earlier proposed background250MiB uploader. No new scheduler, worker identity, signed URL, bucket CORS or broad storage permission.12MiB JSON limit and120s BFF timeout accommodate capped8MiB base64. This is Admin-only; no public CDN/delivery endpoint introduced. Private preview fetches MP4 only when user presses play, then uses temporary Blob URL with controls/playsinline/preload=none and revokes URL on unmount. Poster and thumbnails require same current Admin auth/canonical grant. No token URL. Approved future buyer delivery/CDN/range support must be implemented in publication task; do not treat Admin base64 preview as public delivery.

New tables: media_thumbnail,product_color_image,video_asset,product_video. Runtime scoped SELECT/INSERT plus UPDATE(asset_id,source_id) on color association only. No asset/video approval/delete/IAM/payment/seller-mode rights. Existing DB secrets/private bucket identities unchanged.

Activation: owner-reviewed004 grants and two-service rebuild. Before activation check contracts/API/Web compilation, image and video validation, actual FFmpeg execution in Linux container, rollback-only SQL constraints/role checks. Windows Node subprocess EPERM is environment restriction; don't mark end-to-end normalization passed based only on metadata tests.
